## Automated checks

Run in the project environment:

```powershell
$env:DEBUG = 'false'
python -m pytest
python -m ruff check src tests
```

Validation result: **216 pytest tests passed** (including 20 checkout tests);
Ruff passed. One existing Starlette/httpx deprecation warning remains.

20 checkout tests cover multiple sellers, purchase-price snapshots, reservations,
full rollback after database writes, version conflicts, changed cart lines,
separate-connection simultaneous last-unit and same-key requests, replay after cart
clearing, changed payload/owner, API ownership/auth/input validation, page delivery,
and repeatable migration of a legacy orders table. Committed results are checked
through independent sessions using disposable SQLite files.

`node tests/checkout_ui.mjs` runs the real scripts against DOM/network test doubles:
summary/empty/unavailable states, pending request restoration, timeout/replay using
the same key and body, validation input preservation and GET-only confirmation
retry. This also passed through the session Node runtime. Node is optional for this
script check and is not a runtime dependency of the marketplace.

The host DEBUG was 'release', which Pydantic rejects. Checks set DEBUG=false only
for the command process; no user .env or configuration was modified.

## Browser checks still required

No browser was connected in the implementation session. Script and HTTP checks do
not verify visual layout, browser accessibility or real-user usability. No browser
screenshots or external-user results are claimed.

1. Run python -m src.seed, then python -m src.main using the project environment.
2. Log in as user@example.com / password; add a product and choose Checkout.
3. Check summary and delivery validation. Submit valid details; verify order ID,
   items, total and delivery information on the confirmation page.
4. Reload confirmation (no new order); verify purchased cart lines are gone.
5. Add a product then reduce its available stock through another database session.
   Submit checkout; verify the affected item is identified, input/cart stay intact,
   no order is created and no checkout stock decrement persists.
6. Interrupt a submission with browser network throttling. Retry must reuse the
   same Idempotency-Key and payload; only one order/stock decrement should exist.
7. Check desktop/mobile layout, keyboard focus, guest login return path, seller
   rejection and another buyer's confirmation returning 404.
