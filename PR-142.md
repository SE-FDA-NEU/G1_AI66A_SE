## What changed

The seller analytics API now returns daily, weekly, or monthly seller-scoped
financial time series using the canonical inclusive `from` and `to` filters.
Key enhancements and review fixes:
- **Single SQL GROUP BY query:** Item-level revenue and items sold are aggregated in SQL via `GROUP BY SellerOrder.id` alongside seller order financial totals in a single query, eliminating duplicate queries and Python-level order re-fetching.
- **Unified time bases (BR7):** All metrics use the same effective timestamp (`completed_at` when completed per BR7, falling back to `created_at` for non-completed orders) and share identical period bucketing across daily, weekly, and monthly paths.
- **Field distinction & seller isolation:** `revenue` reflects line-item total (`sum(quantity * unit_price)`), while `completed_revenue` reflects `SellerOrder.total_amount` (accounting for shop vouchers/discounts and shipping fees) scoped strictly to the seller's sub-order without cross-seller leakage from parent `Order.total_amount`.
- **Escrow handling:** Uncompleted orders with escrow status `HELD` or `PAUSED` contribute to `pending_escrow_revenue`; cancelled orders, completed orders, and released escrow are strictly excluded.
- **Cancellation rate:** Documented as a percentage (float, 0.0 to 100.0) across all order statuses.
- **Query parameter cleanup & bounds:** Kept canonical `from` and `to` parameters with a maximum range bound of 731 days, and supported `group_by` aliases (`day`, `month`).
- **Comprehensive test assertions:** Added test coverage asserting exact expected numerical values for all metrics, zero and non-zero cancellation rate, escrow status edge cases, weekly/monthly grouping, and two-way seller isolation.
